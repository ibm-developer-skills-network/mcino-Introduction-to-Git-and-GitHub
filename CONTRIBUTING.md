# Contributing

All contributions, bug reports, bug fixes, documentation improvements, enhancements, and ideas are welcome.

Please take a moment to read this document so that your contribution can be
reviewed and merged quickly.

## Code of Conduct

This project and everyone taking part in it is governed by the
[Code of Conduct](CODE_OF_CONDUCT.md). By participating, you are expected to
uphold this code.

## Bug reports

A good bug report includes:

- the command you ran and the full output you saw
- what you expected to happen instead
- your operating system and Bash version (`bash --version`)

Search the existing issues first — the bug may already be reported.

## Bug fixes

1. Fork the repository and create a branch from `main`.
2. Make your fix in that branch, keeping the change as small as possible.
3. Test the script by running `bash simple-interest.sh` with a few different inputs.
4. Open a pull request describing what was broken and how you fixed it.

## Documentation improvements

Typos, unclear wording and missing examples are all worth fixing. Documentation
pull requests follow exactly the same process as code changes.

## Enhancements and ideas

Open an issue describing the enhancement before writing code, so the idea can be
discussed first. Explain the problem the enhancement solves, not only the
solution you have in mind.

## Pull request checklist

- [ ] The branch is up to date with `main`
- [ ] The commit message explains *why* the change was made
- [ ] The script still runs without errors
- [ ] Documentation was updated if the behaviour changed

Thank you for taking the time to contribute.
